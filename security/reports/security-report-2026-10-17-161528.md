# Portalogia CodeQL Security Report

- **Date:** 2026-10-17 16:15 (local)
- **Branch / commit:** `dev` @ `7952728`, plus uncommitted working-tree changes. The database was extracted from the working tree as it stood at 16:10, so line numbers follow that tree.
- **Tooling:** CodeQL CLI 2.27.2 · `codeql/javascript-all` 2.10.3 · `codeql/javascript-queries` 2.4.7
- **Scope:** `src/`, `scripts/` and `electron.vite.config.ts`, set in `security/codeql/codeql-config.yml`. Tests, `node_modules/` and build output are excluded.
- **Suites run:**
  - `portalogia/security-queries`: 14 custom queries in `security/codeql/queries/`.
  - `javascript-security-extended`: GitHub's standard suite, 103 rules.
- **Reproduce:** `powershell -NoProfile -ExecutionPolicy Bypass -File security/codeql/run-analysis.ps1`. Raw SARIF and CSV are written to `security/codeql/results/`, which is git-ignored.

## Summary

The custom queries model Portalogia's own trust boundaries. They follow handlers registered directly on `ipcMain` and those registered through the local helpers (`handle`, `invokeForTab`, `invokeFromPage`). They recognise the project's sender guards (`chromeWindowOf`, `isChromeSender`, `owns*Contents`, `resolveTabManager`). Taint is followed through `schema.safeParse(raw).data` into file-system, process, network and navigation sinks.

The IPC fixes made since the 2026-10-06 review hold up under machine checking. Of **104 IPC handlers**, 100 authorise their sender. The four that don't are all low-impact:

- `adblock:get-state`
- the per-sender `editable-focus` flag
- two handlers owned by the Ghostery library

The one command-execution flow (`terminal:input` → pty `write`) is bound to the terminal tab's own `webContents` by `ownsTerminalContents`. Every `WebContentsView` and window that renders content is hardened. No preload exposes raw IPC, and both tab-preload shadow roots are `closed`. CodeQL proved that the Markdown reader's single `innerHTML` sink is fed from `DOMPurify.sanitize`. Every `executeJavaScript` call is constant or JSON-serialised.

What remains:

- **One URL-allowlist gap.** `tabs:create` loads its `url` through `normalizeUrlOrSearch` without the `isNavigableUrl` check that `tabs:navigate` applies. `file://host/share`, `javascript://…` and `ms-settings://…` all survive normalisation (checked by running the same logic in Node).
- **An untrusted note can name absolute paths.** A `.md` note can open other notes, or read images into the page, anywhere on disk.
- **One ReDoS** in the editor's math highlighter.
- A set of low-severity hardening items.

Nothing is reachable from an ordinary web page without first compromising a renderer.

**Count after triage: 0 Critical, 0 High, 2 Medium, 6 Low, 4 Informational.** Of the 8 standard-suite results, 2 are false positives (CS-FP-1, CS-FP-2). The remaining 6 are counted as findings CS-003, CS-007 and CS-009.

## Finding details

### CS-001: `tabs:create` skips the navigation allowlist
- **Path (CodeQL):** `registerTabIpc.ts:99` `handle(TabsCreate, …, (request, event) => …createTabAndFocusAddressBar(request.url))` → `TabManager.createTab` → `createBrowserTabState` → `view.webContents.loadURL(normalizeUrlOrSearch(url))`.
- `navigate()` runs the same normalisation and then refuses `!isNavigableUrl(target)`. `createBrowserTabState` doesn't. `normalizeUrlOrSearch` sends any `scheme://host.tld/…` through unchanged, as long as the host looks like a domain or is `localhost`. A `loadURL` called from the main process doesn't fire `will-navigate`, so the `will-navigate` guard at `TabManager.ts:5562` doesn't cover it.
- **Verified** (scratchpad Node script mirroring `src/shared/url.ts`):

  | Input | After `normalizeUrlOrSearch` | `isNavigableUrl` |
  |---|---|---|
  | `file://attacker.example.com/share/x` | unchanged | `false` |
  | `javascript://localhost/%0aalert(1)` | unchanged | `false` |
  | `ms-settings://x.com/` | unchanged | `false` |

- **Not verified:** what Electron 44's `loadURL` actually does with each of these in a sandboxed tab.
- **Reachability:** the chrome page only. `resolveTabManager` refuses tab pages. The address bar goes through `navigate`, which is checked. Session restore (`TabManager.ts:520`) and `window.open` (`:5474`) already filter. So this needs a chrome-renderer compromise, or a future caller that passes an untrusted URL.
- **Fix:** move the `isNavigableUrl` check into `createBrowserTabState`, the single place every tab load goes through, and fall back to `DEFAULT_TAB_URL`.

### CS-002: Note-relative paths may be absolute
- `readImageDataUrl` and `resolveLinkTarget` accept `isAbsolute(text)` as is. `isLocalPathText` blocks UNC and URL schemes, but drive-absolute (`C:\…`) and POSIX-absolute paths pass. A note with `![](C:/Users/<you>/Pictures/id-card.jpg)` loads that file into the Markdown page.
- The Markdown page's CSP and DOMPurify leave no direct exfiltration path today, which is why this is rated Medium rather than High. It still widens what an XSS in the Markdown renderer could steal, from "this note" to "any image on disk".
- **Fix:** resolve relative to the note and then require the result to stay inside the vault root, or the note's directory when there is no vault (`relative(root, path)` must not start with `..` and must not be absolute). Drop the `isAbsolute` shortcut, or limit it to paths inside the vault.

### CS-003: Math-highlight regex
- The pattern is at `MarkdownEditor.tsx:64`. Its probable intent is `/\$\$[^$]+?\$\$|\$(?!\s)(?:\\.|[^$\\\n])+?(?<!\s)\$(?!\d)/g`. Two changes:
  - Escape the escape: `\\.` instead of `\.`.
  - Exclude a real newline in the character class: `\n`, written in the regex literal as `\n`, not `\\n`.
- CodeMirror's `MatchDecorator` runs on every visible line, so one crafted line freezes the editor tab.

### CS-004: Main-process image fetch has no destination policy
- Mitigations already present: a user click is required, `https:` only (redirect target re-checked), no cookies, `image/*` only, a byte cap and a 15 s timeout. What's missing is a rejection of loopback, link-local and private ranges after DNS resolution, so a hostile note can make a click probe internal HTTPS services. Alternatively, route the fetch through a `session` with a proxy or a `webRequest` filter that applies the same policy.

### CS-005: `adblock:get-state` readable by any renderer
- Add `if (!isChromeSender(event)) return null;`, matching `adblock:set-enabled` and `adblock:set-site-allowed`.

## Checked and found sound (by query)

- **IPC sender authorisation** (`ipc-attack-surface`, `ipc-handler-missing-sender-check`): 104 handlers. 41 are wrapped actions, all of which resolve through `resolveTabManager`. The page channels for Markdown, PDF and terminal are bound to the owning tab's `webContents` (`owns*Contents`). `find:result` compares against the active view's `webContents` inside `handleFindResult`.
- **IPC payload validation** (`ipc-payload-not-validated`): every first-party handler passes its raw payload through a zod schema, directly or in the method it delegates to. The only exception is the Ghostery library's handler (CS-010).
- **Command execution** (`ipc-to-command-execution`): the only IPC → process flow is `terminal:input` → `TerminalManager.write`, guarded by `ownsTerminalContents` (an identity comparison of the tab's own view). `markdown:run-code` sends only a block *index*; the code itself is read from main's copy of the note and is not tainted.
- **Window hardening** (`electron-insecure-webpreferences`): 11 `WebContentsView`s and the main `BrowserWindow` all set `contextIsolation: true`, `sandbox: true` and `nodeIntegration: false`, and enable no dangerous flags.
- **Script injection** (`execute-javascript-dynamic-code`): 5 `executeJavaScript` calls. All are constant, imported constants, or `JSON.stringify` (`PageDocumentExporter.buildSerializeScript`).
- **HTML sinks** (`unsanitized-html-sink`): the one sink, `MarkdownReader.tsx:86`, is proven by data flow to come from `DOMPurify.sanitize`. There is no `dangerouslySetInnerHTML`, `document.write` or `insertAdjacentHTML`.
- **Preload bridges** (`preload-exposes-raw-ipc`): 10 `exposeInMainWorld` APIs. None forwards a page-chosen channel or hands a page callback directly to `ipcRenderer.on`.
- **Page preloads** (`page-preload-ui-exposed`): both `attachShadow` calls (`tabComments.ts`, `tabTextBoxes.ts`) are `mode: 'closed'`, and no page-owned element is adopted. SEC-004 from 2026-10-06 is fixed.
- **Persisted state** (`unvalidated-json-parse`): all 11 main-process `JSON.parse` results reach a zod schema.

## Limitations

- CodeQL doesn't follow data through React props/state or across the preload ↔ renderer bridge, so renderer-side flows are only partly covered. The HTML-sink query reports any sink it can't prove sanitised, rather than staying silent.
- Sender authorisation is recognised by guard **name** (`isSenderGuardName` in `lib/PortalogiaIpc.qll`) or by an identity comparison. A guard with a new name will show up as a false positive until it's added there.
- The working tree was being edited while this ran (new channels such as `PdfOpenLink` and `PdfSetPointerMode` appeared between runs). Re-run `run-analysis.ps1` after committing to get stable line numbers.
